## 🚀 GETTING STARTED

### 1. Fork the repository

Create your own fork of AI Vision Hub on GitHub.

### 2. Clone your fork

```bash
git clone https://github.com/xhk-basharat/AI-Vision-Hub.git
```

### 3. Navigate to the project

```bash
cd AI-Vision-Hub
```

### 4. Create a virtual environment

```bash
python -m venv venv
```

Activate it.

**Windows**

```bash
venv\Scripts\activate
```

**Linux / macOS**

```bash
source venv/bin/activate
```

### 5. Install dependencies

```bash
pip install -r requirements.txt
```

### 6. Create a feature branch

```bash
git checkout -b feature/your-feature-name
```

## 🧬 DEVELOPMENT GUIDELINES

Please follow these guidelines when contributing.

### Python Code

- Use clear and descriptive variable names.
- Keep functions focused on one responsibility.
- Follow PEP 8 conventions where practical.
- Handle exceptions appropriately.
- Avoid unnecessary code duplication.
- Document complex logic.

### AI and Machine Learning

- Clearly identify model requirements.
- Document datasets and their sources.
- Explain preprocessing steps.
- Report relevant evaluation metrics.
- Avoid presenting model estimates as guaranteed results.
- Respect the licenses of pretrained models and datasets.

### Security and Privacy

- Never commit passwords, API keys, or secret tokens.
- Do not upload private biometric images.
- Obtain consent before processing face data.
- Validate user inputs and uploaded files.
- Report security vulnerabilities privately.

### Documentation

- Update README.md when project functionality changes.
- Document new API endpoints.
- Include installation requirements for new dependencies.
- Provide examples where appropriate.

## 🔧 SUBMITTING CHANGES

### 1. Review your changes

```bash
git status
```

### 2. Stage your changes

```bash
git add .
```

### 3. Commit your changes

```bash
git commit -m "Add your feature description"
```

### 4. Push your branch

```bash
git push origin feature/your-feature-name
```

### 5. Open a Pull Request

Visit your fork on GitHub and open a Pull Request against the original repository's main branch.

Explain:

- What you changed
- Why the change is useful
- Which files were affected
- What tests you performed
- Whether documentation was updated

---

## 🐛 REPORTING BUGS

When reporting a bug, include:

1. A clear description of the problem.
2. Steps to reproduce it.
3. Expected behavior.
4. Actual behavior.
5. Python and operating system versions.
6. Relevant error messages or traceback.

Never include passwords, secret keys, private images, or personal data in bug reports.

## 💡 FEATURE REQUESTS
